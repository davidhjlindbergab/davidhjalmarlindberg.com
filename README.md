# davidhjalmarlindberg.com

The website of David Hjalmar Lindberg: the front page, a page for each project, and product pages for Andrum (`/andrum/`) and Colobri (`/colobri/`).

Plain HTML, CSS and JavaScript with no build step. Served by GitHub Pages from the root of `main`; `CNAME` holds the custom domain.

## Pages

- **Front page** (`index.html`): ten projects in the order Nakãya, Andrum, Colobri, Avicii, The Last Testament, DINOS, Norrsken, Aware App, Talks, DJ. Each links to its page.
- **Project pages**: `nakaya/`, `avicii/`, `the-last-testament/`, `dinos/`, `norrsken/`, `aware/`, `talks/` and `dj/`, each an `index.html`. Andrum and Colobri link to their product pages.
- **Plugins** (`plugins/index.html`): Andrum and Colobri, each linking to its product page. Every page's menu reads Selected work, Plugins, About, Contact; phones show the first two.
- **One stylesheet** (`style.css`) for the front page, the project pages, the Plugins page and `404.html`: paper `#f4f3ef`, ink `#242420`, Helvetica Neue. Image corners come from `--radius` (tiles) and `--radius-lg` (full-width images), both 16px on phones.
- **Buttons** follow apple.com: 44px pills with 17px regular text, 17px apart. On the main site the links under a project's text are buttons (`.links`: the first filled, the rest outlined); the Andrum page's `.btn` and `.play` use the same size and text. On every pill (buttons and the Colobri page's chips) the words start and end exactly where the round ends meet the straight edge: the side padding is half the height, border included (a circle at an end, like the play dot, sits centred in that round end instead). Pills are as wide as their words, never stretched by the layout (no full-width or minimum-width buttons), so this holds everywhere. The site editor keeps it when it changes a pill's height.
- **Images on hover**: on computers, a project's image on the front page and the Plugins page rests a touch darker and softer in colour, and on hover brightens to full colour and grows slightly (the `.project .image-frame img` rules in `style.css`). Phones and tablets always show the images in full.
- **The Plugins menu**: hovering Plugins rolls Andrum and Colobri down under it (`.menu` in every page's header). Touch screens go straight to the Plugins page.
- **Statistics** (`stats.js`, loaded by every page, and `stats-collector.gs`): the site counts itself, without cookies or anything that identifies a visitor, so there is no cookie question for it.
  - `stats.js` sends each count to a Google Apps Script web app (its `/exec` address is `COLLECTOR` at the top). It counts page views (missing pages as 404); visits, a page view that came from outside the site, with the source (the referring site or `utm_source`), `utm_campaign`, time zone, device, browser, system and language; arrivals at Andrum or Colobri from the rest of the site; the time a page is in view; and clicks on downloads, Buy (also Andrum's in-app Buy, which opens `/andrum/buy/`), Tell me when it's on sale, e-mail links and links out.
  - `stats-collector.gs` is the script's source. It is attached to the Google Sheet "Statistik för davidhjalmarlindberg.com" in David's Google Drive and writes daily totals to its first tab, Data (day, part of the site, measure, key, count, seconds). Once a day it adds equal rows together and turns days older than 120 days into months. To change it, paste the file into the sheet's Extensions > Apps Script, save, and deploy a new version of the same web app (Deploy > Manage deployments > Edit > Version: New version), so the address in `stats.js` stays.
  - The dashboard is a Claude artifact, made from the Dashboard type, that reads the sheet through David's Google Drive connector.
  - `?stats=off` on any page stops the counting in that browser, `?stats=on` starts it again, and `?stats=test` sends that page's counts to the sheet's Test tab.
  - New pages need `<script src="/stats.js" defer></script>` in their head.
- **Meta pixel on Andrum** (`andrum/assets/js/pixel.js`): the same pixel as Colobri (4475247569405091, the dataset named davidhjalmarlindberg.com in Events Manager), asked for with the same cookie question and the same saved answer (`colobri.cookies`), so a visitor answers once for the whole site. It sends PageView, ViewContent, StartTrial (Mac and Windows downloads) and Lead (Tell me when it's on sale). Cookie settings is in the page's footer.
- **Privacy** (`privacy/index.html`): what the site counts, the Meta pixel and cookies, hosting. The footers link to it.
- **Colobri's type**: SF Pro through the system font, with Inter (`fonts/inter-var-latin.woff`, SIL Open Font Licence in `fonts/OFL.txt`) on other devices.
- **Images**: front-page images in `img/work/`, each project's gallery in `img/<project>/`.
- **The DJ page** plays the Borderland 2026 set through SoundCloud's own player.

## Instagram on the front page (`instagram/`)

- **What it is**: a phone with David's Instagram (@david.hjalmar.lindberg) beside the front page's opening. On a computer it swings in from the right edge once, on a visitor's first visit, and its screen wakes as it lands; *Fold away* swings it back to rest ajar at the screen's edge, showing the newest post: beside the intro when there is room, otherwise lower, in the corner under the 'Selected work' line, so it never covers the intro text (`layout()` in `phone.js` works this out from the perspective). A click on it or its tab brings it back. It belongs to the opening screen: scrolling on into the work swings it shut, scrolling back opens it ajar. It knocks once when there are posts the visitor hasn't seen. On phones and tablets a round button with the newest post opens the same screen as a sheet from below (pull it down or tap outside to close); the button shows only at the top of the page and at the contact footer.
- **The screen**: the profile (picture, posts, followers, name, category, website, *Follow*, the highlights, the newest twelve posts) and *Latest posts*, which plays the six newest like stories: tap the right or left side, press and hold to pause, arrow keys, a pause button; it waits while the pointer is on the caption. Every post, highlight and button opens on Instagram in a new tab. Nothing from Instagram loads on the page: no scripts, no cookies, no embeds.
- **Files**: `phone.js` (no build step; loaded with `defer` at the end of `index.html`, starts after the page has loaded and adds `phone.css` itself), `feed.json` (everything the phone shows) and `media/` (web-ready covers: `<shortcode>-s.webp` for the grid, `-l.webp` for the player, `.mp4` clips of the newest reels when the sync makes them, `avatar.webp`, `hl-*.webp`). The visitor's state is kept in their browser (`localStorage`, `ig-phone-v1`): seen once, folded, the newest post they have seen.
- **Keeping it current**: `.github/workflows/instagram.yml` runs `scripts/instagram_sync.py` every night (and on demand from Actions › Instagram › Run workflow). It fetches the profile and newest posts with the Instagram API with Instagram Login, makes the covers (and, with ffmpeg, 15-second clips of the three newest reels), rewrites `feed.json`, commits only when something changed and asks Pages to rebuild. The API can't tell the category, the highlights or which posts are pinned, so those stay as written in `feed.json` (`profile.category`, `highlights`, `pinned`: shortcodes). Until the token below exists the workflow does nothing, and the phone shows the posts in `feed.json` as they are (the first set, of 2 November 2026, was taken from the profile by hand).
- **The token**: the Meta app *David Hjalmar Lindberg site* (app 2691689974595559, in the David HJ Lindberg AB business portfolio, Instagram API use case) has a read-only login configuration, *Website feed (read only)*: a system-user token that never expires, for the Instagram account only, with `instagram_basic`. Its token is the repository secret `INSTAGRAM_TOKEN`; a new one comes from the app's *Use cases › Instagram API › API setup with Unified login › Generate access tokens › Generate token* (David's Instagram account is the app's Instagram tester). The sync reads the account by its Instagram ID, 17841454963593364 (the workflow's `INSTAGRAM_USER_ID`). An Instagram-login token in the same secret also works; it lasts 60 days, and with a second secret `GH_SECRETS_PAT` (a fine-grained GitHub key for this repository with *Secrets: Read and write*) it renews itself.

## The site editor (`/edit/`)

- **What it is** (`edit/index.html` and `edit/editor.js`, no build step): David's visual editor at davidhjalmarlindberg.com/edit/. He clicks text, pictures, links, fonts, sizes, colors and spacing in a live preview of a page and presses Publish, which commits straight to `main` (the messages start with `Site editor:`). It uses his own fine-grained GitHub key (this repository only, Contents: Read and write), kept in his browser; there is no server. The page is `noindex`, and its address settings (`?api=`, `?site=` and the rest) work only on localhost, for testing.
- **What it writes**: texts and attributes change in place in the page's HTML, and everything else in the file stays byte for byte. Style changes go into blocks the editor owns:
  - for one page, `<link id="site-editor-fonts">` and `<style id="site-editor">` at the end of its `<head>`;
  - for every page that uses `style.css`, an `@import … /* site-editor:fonts */` line at the top of `style.css` and a `/* site-editor:start */ … /* site-editor:end */` block at its end.
  - An element styled on its own carries a `data-se="…"` marker that its rule points to. New pictures are made web-ready (WebP, at most 2560 px) and saved next to the picture they replace, or in the page's `images/` folder.
- **Editing the site anywhere else**: pull `main` first, since pages can change from the editor at any time. Keep the editor's blocks and `data-se` markers; to tidy one up, move its rule into the page's own styles and remove the rule and its marker together. Leave `edit/` alone unless David asks.
